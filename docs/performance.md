# 加载与刷新优化验证

基线为提交 `a3b2c25`，优化版本为本次源码。两者均在同一设备上使用 Chromium、1440 × 900 视口测量，每组取三次的中位数。慢 WiFi 模拟条件：70ms 延迟、下载 200 KiB/s。时间会随设备、网络和浏览器缓存变化。

| 指标 | 基线 | 优化后 |
| --- | --- | --- |
| 首次静态资源传输量 | 614 KiB | 298 KiB |
| 慢 WiFi 首次页面 load 事件 | 2.90 秒 | 2.02 秒 |
| 慢 WiFi 首次有内容绘制（FCP） | 0.93 秒 | 0.64 秒 |
| 再次访问时静态资源网络请求 | 12 次 | 0 次 |

静态资源统计包含脚本、样式、字体和图标，不包含 HTML 与实时接口；再次访问仍会请求页面和最新数据。计时反映整个加载过程，不能等同于接口耗时。

## 改动

- JS、CSS 与 SVG 在服务启动时预压缩一次，按浏览器能力提供 gzip，无运行时新依赖。
- 静态资源 URL 携带内容摘要，启用长期缓存；文件改变时 URL 自动更新。未带版本、版本不匹配的资源仍需验证缓存。
- Inter 常用字库从 352,240 字节拆为 128,496 字节核心字库；原字体保留为扩展字符回退。预加载中英文核心字库，保留原有字体外观与完整覆盖。
- 数据行与网卡节点复用；文字未变时不重新写入；服务数据和语言均未变时不重建服务区。验证覆盖数据变化、状态颜色与语言切换。
- HTML、API 与错误响应保持 `no-store`，不压缩或缓存账号与密码响应。图表与采样频率不变。

## 复现

运行只读预览后执行：

```bash
.venv/bin/python docs/performance_check.py --runs 3
```

报告输出到 `docs/performance-report.json`（Git 忽略）。计时阶段仅访问实际静态资源与只读监测接口；节点复用和敏感交互检查使用隔离数据，不扫描或切换网卡。不要通过 Playwright 路由拦截计时阶段的 API，启用路由会禁用浏览器 HTTP 缓存，影响重复访问结果。

验证通过：94 项后端测试，`docs/theme_check.py`、`docs/chart_check.py`、`docs/flow_check.py` 及上述性能检查。字体分区检查确认两个字体家族的核心与回退 Unicode 范围互不重叠，罕见字符可触发回退字体加载。

## 后续：减少刷新等待

Linux 与桌面采集器共用采集锁和短时发布锁。外部命令、设备读取、进程枚举在发布锁外执行，完整采样及其进程列表、历史点一起发布。采集中收到请求时返回上一份完整数据，下一次正常轮询读取新数据；首次启动还没有数据时仍需等待首份采样。正常采样间隔保持两秒。

在同一设备、五次测量中，故意给后台的一项采集增加 250ms 延迟：原来的快照读取中位数约 262ms，调整后约 0.2ms。此数值仅反映采集与读取争用时的 Python 快照读取耗时，不包含网络、浏览器绘制或首次页面加载。数据采集本身并未因此加速。

首次进程列表与系统状态并行请求；慢的状态响应不再阻挡进程列表。已有的进程刷新间隔与手动刷新行为保留，首次请求不会因并行加载而重复。

复现：

```bash
.venv/bin/python docs/refresh_check.py
.venv/bin/python docs/refresh_ui_check.py
```

新增检查覆盖 Linux 与模拟 Windows 后端在慢采集时的读取、未完成数据隔离、采集失败恢复，以及浏览器并行加载、手动刷新、错误恢复、进程选择与节点复用、中英文和手机布局。当前共 97 项后端测试通过，曲线动画检查通过。

## 后续：服务内存

减少采样中无消费者的深拷贝，并复用已经完成的进程列表作为发布数据。采集器每轮新建进程记录，HTTP 读取仍返回独立副本，因此慢采集期间的数据隔离与进程校验保持有效。

Linux systemd 服务增加 `MALLOC_ARENA_MAX=2`，减少 glibc 多线程堆保留的空闲空间。原有六个 HTTP 工作线程、采样间隔、十分钟历史、静态资源缓存和字体全部保留。更新脚本为旧服务补充默认值，并保留原有显式设置与用户 drop-in 配置。此项分配器设置针对 Linux/glibc；Windows 不依赖它。

在当前设备使用同一源码，分别以默认分配器设置和上述服务设置启动全新只读进程。每组测量三次，取中位数；六个并发客户端，每次共 2,400 次系统、进程与页面 GET 请求。常用负载和读取完整中文回退字库后分别记录内存：

| 指标 | 默认设置 | 优化设置 |
| --- | --- | --- |
| 启动后 RSS | 36.6 MiB | 36.5 MiB |
| 常用负载后 RSS | 40.8 MiB | 39.6 MiB |
| 中文回退字库传输后 RSS | 42.6 MiB | 41.1 MiB |
| HTTP 请求耗时中位数 | 7.7ms | 7.9ms |
| HTTP 请求耗时 P95 | 24.3ms | 22.2ms |

常用负载节省约 1.2 MiB（3%）；启动时本身可压缩的部分很少。请求耗时存在运行波动，本轮未观察到明显速度下降。RSS 包含进程驻留的共享库页，并不等于独占内存，也不能用虚拟地址空间 VSZ 代替。实际占用会随系统进程数、客户端数量和访问内容变化。

复现时依次执行，避免与其他压测或测试并行运行：

```bash
.venv/bin/python docs/memory_check.py --arenas default --output /tmp/helloboard-memory-default.json
.venv/bin/python docs/memory_check.py --arenas 2 --output /tmp/helloboard-memory-tuned.json
```

脚本使用示例配置，只运行临时只读预览进程，不扫描或切换网络；结束后清理子进程。现有数据隔离检查、部署设置保留与重复升级检查通过，当前共 98 项后端测试通过。
